# JEI 跨服缓存模式（mq.4）

在 `config/justenoughthreads-client.toml` 现有的 `[general]` 段中修改：

```toml
[general]
enabled = true
cacheMode = "ACCURATE"
pinyinDictionaryCache = true
```

不要重复添加 `[general]` 段。旧版的 `sessionRuntimeCache` 已移除，升级默认采用 ACCURATE。

| 配置值 | 行为 | 取舍 |
| --- | --- | --- |
| `ACCURATE` | 每次重建当前子服配方和物品映射，复用文本的拼音索引 | 保持当前子服的数据；仍有配方注册和其他加载时间 |
| `FULL` | 同一网络连接跨服时复用已完成的整份 JEI，不校验配方差异 | 跳过 JEI 重建；子服有差异时可能显示旧配方或旧物品 |

首次进服都需要完整加载。断开连接、重启客户端、F3+T 或 JEI 手动重载会重新构建。
修改模式不会热替换正在显示的配方；配置被客户端读取后，在下一次跨服配方同步时选择是否复用。
如需立即更新当前服合成表，用 F3+T 或重新连接。服务器仍决定配方是否可以实际合成。

准确模式下，拼音缓存只保存字符串及其搜索结构；每个 JEI 搜索器都新建当前物品集合。
查询时用当前集合筛选共享字典的结果，旧子服的字符串不会带回旧物品对象。
字典最多保存 100,000 个词和 8,000,000 个 UTF-16 字符，超过限额仍使用原版局部索引，不删减结果。
拼音设置变化沿用 JECharacters 自己的刷新机制，资源重载会释放共享字典供下一次重建。

## 日志验证

- 全部缓存命中：`JEI FULL cache HIT`，后面不应紧接一次 `Starting JEI` 重建。
- 拼音部分缓存：`JEI pinyin dictionary cache`，`reusedPuts` 表示免于重新插入拼音树的次数；
  同时仍有 `Starting JEI took`，这是准确模式的正常行为。
- `overflowPuts` 不为零意味着达到了共享字典上限，超出的输入仍正常建立局部索引。

mq.4 已通过完整构建、11 项回归运行器和实际 JEI／JECharacters JAR 接口检查。
包含真实 PinIn 1.6.0 中文、拼音、模糊音、空查询、重复词、运行时新增、跨服旧对象隔离与溢出路径对照测试。
这不等于已验证整合包的游戏内稳定性或具体提速幅度，仍需实际进服与跨服测试。
