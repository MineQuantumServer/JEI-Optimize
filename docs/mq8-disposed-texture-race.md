# mq.8：动态纹理关闭与排队初始化竞争

诊断与修复日期：2026-09-30。报告环境：Minecraft 1.21.1、NeoForge 21.1.251、
JEI 19.57.0.449、Just Enough Threads 0.14.2-mq.7。

## 已确认的崩溃路径

17:58:31.033 的首次致命错误发生在渲染线程的 `DynamicTexture.lambda$new$0`：
`this.pixels` 为 null，调用 `getWidth()` 失败，来自 `RenderSystem.replayQueue()`。

本地同版本 Minecraft 源码和生产字节码确认：带 NativeImage 的纹理构造器在后台执行时，
把 GPU 初始化排到渲染队列；该回调直接读取当前 `pixels`。`close()` 会关闭图像并将字段
清为 null，但原版排队回调没有处理关闭。关闭发生在回放之前即可触发报告中的空指针；
关闭与回调同时执行也有竞争，因此只在回调开头检查一次 null 并不足够。

## 插件归因的边界

Thaumcraft 配方注册从约 17:58:28.211 到 17:58:35.472 在后台线程执行，覆盖崩溃时刻。
它是重点排查对象，但队列栈不包含纹理创建者，不能凭时间线认定创建者就是 Thaumcraft。
本地 `4.2.3.5-1.21.1-port.0.1.0-20721` JAR 的类引用扫描未发现直接引用 DynamicTexture。
其配方注册确实读取客户端世界、玩家，且修复配方发现会创建 AnvilMenu 并调用物品／菜单回调。
这足以支持把该插件放回客户端线程，但不能证明其间接调用就是本次纹理的来源。

FTB JEI Extras、Ender IO 等空世界错误出现在首次致命错误之后，不能用来解释第一次崩溃。
附件中的其他分析作为线索使用，没有沿用其对具体创建者的确定性结论。

## 修复行为

1. NeoForge 客户端中的动态纹理排队初始化、关闭和 `setPixels` 共享同一对象监视器。
   回放时若图像已关闭，退出该初始化任务；有图像时执行原来的初始化，真实上传错误仍传播。
   关闭不会在初始化中途释放该纹理自己的图像，图像替换使用同一规则。
2. 后台创建纹理时记录线程、当前 JEI 插件与阶段、直接调用者。
   跳过关闭纹理时输出 `skipped deferred initialization of a disposed DynamicTexture; creator:`，
   以便从实际客户端日志确认来源。
3. 内置 `thaumcraft:jei_plugin` 的客户端线程规则，等待世界、玩家和连接就绪后执行。
   现有配置无需添加新列表项；仅修改默认列表不能修复已有配置，所以规则独立于用户列表。
4. 纹理补丁检查字段、构造器、关闭和替换接口，以及已知排队方法的宽高读取／上传调用。
   支持生产环境 `lambda$new$0` 和开发环境 `method_22793`；接口改变时退出适配。
   纹理补丁仅针对 NeoForge 构建。启动时 `general.enabled=false` 不加载它；运行时关闭
   总开关会使用原方法。

这里处理的是 DynamicTexture 自身关闭／替换造成的报告路径。
外部代码绕过纹理对象直接关闭 NativeImage、其他 OpenGL 错误、第三方插件自行启动的线程，
仍需各自诊断。已关闭资源的旧初始化任务退出，不会重新创建该资源。

## 验证

- NeoForge 1.21.1 完整构建与 16 项回归运行器通过。
- 新测试运行实际编译出来的包装方法，将 NativeImage 的类型替换为普通对象以避免 OpenGL：
  重现原回调的关闭后解引用，验证受保护路径、正常初始化、并发关闭等待、图像替换、
  错误传播，以及总开关关闭时的原版行为。
- 检查生产 Minecraft 1.21.1 字节码和打包产物，实际 JEI 19.57.0.449 与 JECharacters 4.5.29 接口检查通过。
- 独立真实客户端：NeoForge 21.1.235、JEI 19.27.0.340、MixinExtras 0.5.3。
  测试模组在后台创建并关闭纹理，并短暂让渲染线程等待关闭完成，以保证关闭先于回放。
  正常纹理在渲染线程初始化并关闭；随后在渲染队列中加一个验证回调。
  22:55:41.625 先出现受保护纹理的跳过日志，再出现
  `JET TEXTURE PROBE PASSED: render queue continued after disposed texture initialization`。
  此测试确认真实 Mixin 应用和 GPU 渲染队列行为，测试模组不会打入发布 JAR。
- 尚未在反馈者的完整整合包中验证 NeoForge 21.1.251 下的进服与连续跨服。

## 使用和性能取舍

完全退出游戏后，移除旧 Just Enough Threads JAR，换入 mq.8；保留原配置即可。
FULL 模式仍可复用已完成的同连接运行时，首次完整加载仍执行注册。
Thaumcraft 的注册回到客户端线程后，首次加载可能有短暂卡顿；这项取舍是避免在后台调用
尚未确认线程安全的客户端逻辑。没有本轮实测数据证明整包加载时间缩短。

若仍崩溃，请保留本次启动完整日志与新崩溃报告；新创建来源日志可进一步定位实际触发者。
需要临时排查异步加载时，配置是现有 `[async]` 段中的 `asyncStartup=false`，然后重启。
此选项关闭异步启动，FULL 配置仍按原规则决定是否复用已完成运行时。
