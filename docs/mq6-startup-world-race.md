# mq.6：进服后 JEI 消失的修复

反馈客户端使用 mq.5、JEI 19.57.0.449 和 JECharacters 4.5.29。

日志中的因果链：

- 16:28:19，`jei:neoforge_gui` 注册界面时报 `minecraft.level must not be null`。
- 16:28:21，JEI 仍输出 `Starting JEI took 19.84 seconds`。JEI 会捕获插件异常，
  因而这条日志不保证界面初始化成功；运行时可以包含 JEI 自带的 Dummy 占位接口。
- 16:28:24，mq.5 输出 `JEI FULL cache HIT`，跳过重建并保留了不完整的界面。
- 后续一次完整重建于 16:30:03 结束，成功构建了 37,752 个物品的索引。
  日志无法证明该次重建后的实际画面是否正常，也不能确定截图拍摄时刻。

mq.6 的处理：

1. 后台启动先等待客户端世界、玩家和连接就绪；客户端继续正常处理网络和渲染。
2. GUI 注册在客户端 tick 中重新检查世界就绪，检查与实际回调在同一线程执行。
3. 断线、重新启动或取消时，旧任务作废，不能在新世界就绪后继续发布。
4. FULL 缓存要求物品列表、搜索器和配方界面都不是空值或 JEI 的 Dummy 实现；
   不完整时记录 cache MISS，并在本次配方同步中走正常重建。

默认模式仍为 FULL。首次进服仍需正常加载，子服配方差异仍属于 FULL 模式的既有取舍。

完整构建和 12 项回归运行器通过；打包后的 JAR 还使用实际 JEI 19.57.0.449
验证了 Dummy 接口拒绝缓存，并通过 JEI／JECharacters 接口检查。
尚未在反馈玩家的客户端实测。

验证时先退出游戏，删除旧版 justenoughthreads JAR，放入 mq.6，避免两个版本共存。
首次加载期间可以打开背包，加载完成后确认物品列表与配方查询；再跨服检查缓存命中。
如果仍出现消失，请保留该次完整日志，并说明发生在首次进服还是跨服之后。
